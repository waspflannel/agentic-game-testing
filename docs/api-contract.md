# Dashboard API contract v1

All JSON mutations require `X-ASHAD-Request: 1`. No credentials in browser storage. Errors use `detail` (string or JSON). Times are UTC Unix seconds; IDs are strings. Empty observations remain null/unknown. Subscription usage has no dollar price; its null cost means not applicable.

`GET /api/bootstrap` returns `{settings, ai, builds:[], workers:[], accounts:[], fixtures:[], scenarios:[], runs:[], usage:[], defaults:plan, model_options:[{id,label}]}`. Catalog entries have `id,name`; scenarios have `id,revision,title,plan`; runs have `id,state,created_at,plan,players:{id:status},progress,ending_reason,investigation_deadline,validity,evidence_status`. Cached `ai` = `{configured,status,model,api,auth_method,billing,message,plan_type?}`, with `api=codex`, `auth_method=chatgpt`, `billing=subscription` and `model` naming the model checked. Optional `available_models` lists the supported models advertised by the account. `configured` means signed in; only `status=ready` confirms model availability. New runs record `api=codex,billing=subscription` and pin the model selected in `plan.model`. `plan.model` defaults to `gpt-6-luna`; supported alternatives are `gpt-6-sol`, `gpt-6.1-sol` and `gpt-6-astra`. Legacy draft reasoning_effort is discarded on validation; historical runs remain unchanged.

`POST /api/plan {intent,build_id}` returns `{plan,validation}`. `POST /api/validate {plan}` returns `{valid,errors:[],warnings:[]}`. `POST /api/scenarios {plan,scenario_id?}` returns scenario. `POST /api/launch {scenario_id,revision,idempotency_key}` returns run; explicit launch only. `POST /api/runs/{id}/rerun {idempotency_key,build_id?,exploratory?,plan?}` creates a new Draft scenario (user must Launch).

Plan shape: `{title,intent,primary_goal,assumptions:[],build_id,transport:{mode:'enet'|'steam',app_id:null,host_address:null,port:7800},world_setup:{mode:'fresh'|'saved'|'continue',fixture_id:null,character_policy:'fresh'|'restore',identity_mapping:{}},players:[{id:'player-1',name:'Player 1',role:'host'|'joiner',goal:'Complete the full demo',goal_id:'demo_wrapup_moar',worker_id:null,account_id:null,identity:null,initial:true,required:true,context_policy:'repository'|'reduced'|'instructions',profile:'cooperative',cooperation:'team'}],events:[{id,actor,action:'join'|'disconnect'|'rejoin',trigger:'elapsed'|'milestone'|'event'|'manual',value, time_basis:'run'|'world_ready',dependencies:[],timeout_seconds:120,retries:0,overdue_policy:'run_when_valid'|'skip'|'reschedule',failure_invalidates:true}],success_criteria:{predicate:'quest_completed',target:'demo_wrapup_moar',quantity:null,quantity_scope:'host_current_inventory',corroboration_seconds:10,require_all:true,side_goals:[]},handler_policy:'cooperative_vote',balancing_targets:[],stall_policy:{version:1,investigation_timeout_seconds:1800,observation_max_age_seconds:60,simulation_timeout_seconds:30,divergence_seconds:30,no_progress_seconds:300,invalid_actions_threshold:5},limits:{duration_seconds:null,spend_usd:null,storage_bytes:10737418240},evidence_policy:{fps:5,quality:75,pre_seconds:30,post_seconds:30,rolling_seconds:120,retention:'until_explicit_deletion'},seed:null}`.

`GET /api/runs/{id}` full run with `incidents,findings,usage,events` last 200; `GET /api/runs/{id}/events?after=0&limit=200&search=` paginated `{events,next,total}`. `GET /api/runs/{id}/report` `{markdown}`. `GET /api/runs/{id}/players/{player}/frame` JPEG or 503. `POST /api/runs/{id}/control {command:'pause'|'resume'|'stop'|'terminate'|'extend'|'manual_event'|'goal',reason?,command_id,seconds?:1800,event_id?,player_id?,goal?}`. `POST /api/runs/{id}/flag {description,expected?,players?:[]}`. `POST /api/runs/{id}/review {}` AI saved evidence review. `POST /api/incidents/{id}/review {status,classification,note,merge_into?:id|null}` review and reversible merge. Status `suspected|confirmed|expected|unresolved|merged`; human classification `game_defect|controller_failure|infrastructure_failure|tutorial_confusion|balance_concern|expected_behavior|unresolved`.

`GET /api/compare?run_ids=id1,id2` returns `{runs,differences,attempts,limitations}`. `POST /api/settings {concurrent_sessions,...}` updates settings.

ChatGPT authentication uses the official Codex SDK, with an isolated ASHAD home and OS keyring. These endpoints never accept API keys:

- `GET /api/settings/codex/status` reads current account/model availability and returns the `ai` status object directly; it does not run inference. Account limits may be returned as optional `rate_limits`.
- `POST /api/settings/codex/login {}` starts managed browser OAuth and returns `{auth_url,login_id}`. The dashboard links only to HTTPS `auth.openai.com` or `chatgpt.com`; the human completes sign-in. The dashboard polls status for up to five minutes, then offers manual refresh.
- `POST /api/settings/codex/login/cancel {}` cancels pending sign-in and returns current status.
- `POST /api/settings/codex/logout {}` signs out the ASHAD connection and returns current status. Login/logout require active bots to be paused or stopped and queued runs to be stopped; pending sign-in blocks launch/resume. Authentication changes are serialized with those lifecycle operations. The desktop/global CLI connection is separate.

The former `/api/settings/key` routes are removed. Account status and validation do not create model turns.

Catalog mutations `POST /api/builds`, `/api/workers`, `/api/accounts`, `/api/fixtures` accept entity JSON. Builds `{id?,name,manifest_path}` imports verified manifest. Workers `{id?,name,url,token,desktop_url,host_address,enabled:true}` token write-only credential store. Accounts `{id?,name,worker_id,steam_id,app_id,readiness:'human_sign_in_required'|'ready'}` readiness only confirmed by worker diagnostics. Fixtures `{id?,name,path}` reads package manifest. `POST /api/workers/{id}/probe {}`, `/steam/start {}`, `/steam/finish {}`, `/steam/status {}`, `/steam/verify {account_id,build_id}`; official Steam setup opens within that worker desktop, UI links its `desktop_url`. `POST /api/runs/{id}/fixtures {name}` requests saved-start package from stopped workers where export possible. Catalog deletion `DELETE /api/{kind}/{id}` rejected when referenced by active lease.

Settings defaults: concurrent_sessions=1, storage_reserve_bytes=1073741824, duration_seconds=null, spend_usd=null. Hardware returned in bootstrap settings `hardware:{cpu_percent,memory_percent,memory_available,disk_free,gpu:null}`. `spend_usd` remains accepted for saved-schema compatibility but validation warns that it does not apply to subscription-backed Codex. New draft defaults set it to null.

New usage rows record `api=codex,auth_method=chatgpt,billing=subscription,estimated_cost_usd=null` and the actual selected `model`, purpose, latency, status, and optional returned token usage/thread/turn IDs. The UI labels billing as **Subscription** and computes a separate API-price estimate from reported token counts and the documented model rate. Live run totals and the Usage & capacity instance table group by `run_id`, not title; unassigned usage is separate from the combined instance total. Unknown usage remains unknown/partial. Historical metered rows retain their recorded costs and pricing basis; they are never converted to subscription usage.

`GET /api/runs/{id}/evidence` returns retained files with same-origin URLs, gaps and status. `POST /api/runs/{id}/evidence/collect {}` transfers available worker evidence; `GET /api/runs/{id}/files/{path}` serves only files inside that run's evidence directory. `POST /api/runs/{id}/reconcile {}` retries teardown and releases reservations only after confirmation. `POST /api/findings/{id}/review {status,note?}` accepts `accepted|rejected|needs_evidence|unresolved`. `GET /api/builds/{id}/catalog` returns the pinned build's goals, recipes, items and drops.

Steam verification requires an idle, unleased worker and checks the registered account against the selected build's real App ID using a capture-disabled probe. Account registration cannot assert readiness. Item quantity means the host's current Inventory/Hotbar only; required side goals are listed in `success_criteria.side_goals`. Draft duration defaults come from global settings. See `ashad/models.py` and FastAPI `/openapi.json` for the full implemented schema.

Controls accept an optional ledger reason. On Resume, supplied text becomes recovery_instruction for subsequent decisions until the next Resume; a blank Resume clears it. Terminate requires no reason or typed confirmation. Paused/investigating runs expose `pause:{category,reason,players,started_at,recovery}`. Each player exposes `agent_status` with phase/detail/timestamps and optional last_error/action_id/wait_until. See [current setup and recovery](../README.md).

Human takeover uses explicit same-origin mutations:

- `POST /api/runs/{run_id}/players/{player_id}/takeover {}` pauses every bot, cancels pending inference, then starts the selected launched player's desktop viewer. Returns `{desktop_url,password,run}` with `Cache-Control: no-store`. The URL contains no credentials; `password` is the worker's desktop-only credential, returned only in this response and never stored with run/evidence data. Missing desktop URL/password or an unavailable player fails before opening access.
- `POST /api/runs/{run_id}/takeover/finish {reason?:"",resume?:true}` closes desktop access and resumes bots by default. Instructions are optional; blank clears the previous recovery instruction. `resume:false` closes access while leaving the run paused. The worker must confirm closure before any bot can resume; an ambiguous or failed close retains human ownership and paused state for retry. Duplicate completion after a successful handback is harmless.

Active takeover is represented by `run.human_control:{player_id,worker_id,started_at,desktop_url,status}` without a password; status distinguishes opening, active and unknown acknowledgement. Only one player can be taken over at a time. A takeover enters `Paused`, cancels any investigation deadline, and preserves duration/storage limits. Closing a browser tab is not a lifecycle command and never resumes bots. Generic Resume closes desktop access first. Generic `/control` rejects `takeover`/`takeover_finish`; use the dedicated endpoints above.
